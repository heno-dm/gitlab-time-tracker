# AGENTS.md

## Project Shape
- This is a GNOME Shell extension, not a Node/Python project; there is no package manifest or JS test runner in the repo.
- Runtime entrypoint is `extension.js`; preferences entrypoint is `prefs.js` via `metadata.json` `settings-schema` and `gettext-domain`.
- Dialog/UI modules are loaded directly by the extension: `issueSelector.js`, `reportDialog.js`, and shared `avatarLoader.js`.

## Commands
- `make build` is the main verification step; it cleans, compiles `schemas/`, compiles `.po` files into `locale/`, and packages with `gnome-extensions pack`.
- `make install` runs `make build`, removes the installed extension, then installs `build/timelogs-extension@heno-dm.github.io.shell-extension.zip`.
- `make test-shell` installs first, then starts a nested Wayland GNOME Shell for manual testing.
- `make test-prefs` installs first, then opens preferences with `gnome-extensions prefs timelogs-extension@heno-dm.github.io`.
- `make pot` updates `po/timelogs-extension@heno-dm.github.io.pot`, rewrites `po/LINGUAS` from existing `.po` files, and merges translations.

## Generated Files
- Do not commit generated build artifacts: `build/`, `locale/`, `schemas/gschemas.compiled`, or compiled `*.mo` files; they are ignored and regenerated by `make build`.
- If adding GSettings keys, update `schemas/org.gnome.shell.extensions.timelogs-extension.gschema.xml` and keep `prefs.js`/runtime access in sync.
- If adding user-visible strings, wrap them for gettext and run `make pot`; the Makefile extracts from `extension.js`, `issueSelector.js`, `reportDialog.js`, and `prefs.js`.

## Runtime Gotchas
- GitLab API calls use libsoup async APIs and `PRIVATE-TOKEN`; keep URL construction on `/api/v4` consistent across modules.
- Timer/project persistence is stored as JSON in the GSettings `timer-state` string; changes to that shape affect restore behavior after lock/logout/restart.
- `metadata.json` currently targets GNOME Shell 46-49 and UUID `timelogs-extension@heno-dm.github.io`; package names and schema/gettext domains depend on that UUID.

## Manual Verification
- For packaging/schema/translation changes, run `make build`.
- For Shell UI behavior, use `make test-shell` when GNOME Shell tooling is available.
- For preference changes, use `make test-prefs` when GNOME Shell tooling is available.
